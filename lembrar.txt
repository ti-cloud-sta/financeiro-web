============= LEMBRETES VPS - ROTINA DE BACKUP =============

ATENÇÃO antes de implantar (levantado em 05/10/2026):
   - O projeto na VPS fica em /root/projects/financeiro-web (não em /var/www).
   - O backup_rotina.py lê o arquivo backend/.env (pasta do script/..), mas na VPS só existe o .env da raiz.
   - O script chama "mysqldump" direto no host, e o MySQL roda dentro do container financeiro-web-db-1:
     conferir se o host tem o cliente mysqldump e se ele alcança o banco (porta 127.0.0.1:3306).
   - Detalhes da VPS: .agents/context/infraestrutura-vps.md

1. Atualizar o arquivo .env lá na VPS, adicionando as variáveis novas do SMTP:
   SMTP_SERVER=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER='ti-cloud@stamaria.ind.br'
   SMTP_PASS='SUA_SENHA_DE_APP'
   EMAIL_DESTINO='ti-cloud@stamaria.ind.br'

2. Criar a "Senha de App" no Google Workspace:
   - Fazer login com 'ti-cloud@stamaria.ind.br' no navegador
   - Ir em Gerenciar Conta -> Segurança -> Verificação em 2 Etapas
   - Criar "Senhas de app" e copiar os 16 caracteres para colocar no .env

3. Testar o Backup na VPS:
   - Rodar manualmente na VPS: python3 /root/projects/financeiro-web/backend/scripts/backup_rotina.py
   - Checar se o e-mail chegou certinho com o ZIP anexado.

4. Agendar e Ativar o Cronjob:
   - Rodar 'crontab -e'
   - Inserir a linha: 0 6 * * * /usr/bin/python3 /root/projects/financeiro-web/backend/scripts/backup_rotina.py >> /var/log/backup_erp.log 2>&1
     (o host da VPS roda em UTC: 06:00 UTC = 03:00 de Brasília)
   - Garantir que o serviço do cron esteja ativado rodando (ex: 'sudo systemctl enable cron' e 'sudo systemctl start cron').

============= LEMBRETES - NOVA TABELA DE LOG (nfPendencias) =============

1. Criar a tabela de log no Banco de Dados (MySQL):
   - Criar script SQL para a nova tabela `log_nfpendencias`.
   - Campos sugeridos: `idLog`, `idnfpendencias` (FK), `acao` (INSERT, UPDATE, DELETE), `detalhes` (JSON contendo o "antes e depois" dos campos), `idUsuario` (responsável), `dataHora`.

2. Implementação no Backend (FastAPI):
   - Criar o modelo SQLAlchemy (`LogNfPendencia`) na pasta `backend/app/models/`.
   - Definir a estratégia de gravação: 
     a) Via Triggers no MySQL (garante captura de qualquer mudança, até direto no banco).
     b) Via SQLAlchemy Events (`after_update`, `after_insert`).
     c) Manualmente no `InadimplenciaService`, aproveitando o array `mudancas` que já mapeia o que foi atualizado pela planilha/Datasul.
   - Criar uma rota (ex: `GET /api/v1/inadimplencia/pendencias/{id}/log`) para expor esses dados.

3. Frontend:
   - Adicionar uma aba "Auditoria" ou botão no modal de detalhes da pendência.
   - Renderizar as mudanças usando uma tabela estilo SaaS, parseando o JSON de `detalhes`.
